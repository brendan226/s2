# s2

This project was born after wanting to build a game engine in simple C and constantly trying to navigate the issue of multiple graphics apis, compilers/build systems, windowing, debug UI's and direct interaction with modern GPUs. After graduating from learnopengl.com, I moved to vulkan for more control only to be disappointed again when finding out vulkan wants you to stage your memory in a buffer on the CPU, copy it and then upload it to your GPUs VRAM. Why? Asking this question lead me to this article: https://www.sebastianaaltonen.com/blog/no-graphics-api. Using CUDA we have access to direct allocations on the GPU, and the ability to bypass the staging buffer, so no PCIe upload. The same principle applies to texture binds, we no longer need to ask the cpu permission. Vulkan then becomes just the display driver. it's a win-win, we get to use the GPU and NVIDIA can keep their driver closed. This is not a graphics api, nor is it the game engine I set out to build. This is simply an effort to give you the tools to effectively communicate with your NVIDIA GPU.
